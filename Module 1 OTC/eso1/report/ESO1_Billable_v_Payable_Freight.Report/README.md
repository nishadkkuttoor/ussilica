# ESO1 Billable v Payable Freight — PBIR Report

PBIR (PBIP enhanced report) definition rendering `001 OTC Reports/ESO1_report_wireframe.md`, **rebound (2026-06-23)
to the single-fact `billable_payable_freight` Direct Lake model** (`fact_sales_order_freight` +
`dim_customer`, `dim_carrier`, `dim_item`, `dim_branch_plant`). See `docs/ESO1_gold_layer_design.md`.


## Dataset binding
`definition.pbir` uses **`byPath`** → `../billable_payable_freight.SemanticModel` — a local TMDL Direct Lake model
generated by `report/generate_tmdl_semantic_model.py` (matches the workspace model built by `nb_semantic_model_eso1`).
Before refresh, fill the SQL endpoint placeholders in
`billable_payable_freight.SemanticModel/definition/expressions.tmdl`
(`<SQL_ANALYTICS_ENDPOINT>`, `<LH_JDE_GOLD_DATABASE>`). All 26 report field references resolve against this model.

## Visual ↔ model bindings (after rebind)
- Cards: `[Total Billable]`, `[Total Payable]`, `[Total Variance]`, `[Total CM %]` (measures on `fact_sales_order_freight`).
- Column chart: axis `fact_sales_order_freight[actual_ship_date]`; values `[Total Billable]`, `[Total Payable]`.
- Bar chart: axis `dim_carrier[carrier_name]`; value `[Freight Variance]`.
- Detail table: `fact_sales_order_freight[order_number]`, `[shipment_number]`, `dim_customer[customer_name]`,
  `dim_carrier[carrier_name]`, `fact_sales_order_freight[freight_handling_code]`, `[route_number]`, plus
  `[Total Billable]`, `[Total Payable]`, `[Freight Variance]`, `[Freight CM %]`.
- Slicers: `fact_sales_order_freight[company]`, `dim_carrier[carrier_name]`, `fact_sales_order_freight[shipment_number]`.

## Changes made during the rebind
- All measure/column references moved from the old `fact_freight_audit` / `fact_sales_order_line` / `dim_shipment` /
  `dim_address_*` objects to the new single-fact model.
- **Obsolete fields remapped** (the new model drops cost & status per the spec): `units_transaction_qty_unconv` →
  `quantity_shipped`; `% High-Confidence Cost` card → `[Freight Shipments]`; `has_freight` axis →
  `freight_handling_code` (FHC); the line-detail **Status** column was removed (no longer modelled).
- For freight $, the model's measures dedup to shipment grain (`SUMX(VALUES(shipment_number), MAX(bucket))`) so
  line-level placement never inflates totals.

## Baked into the JSON (2026-06-23)
- **Active-rows filter** — report-level `filterConfig` on `fact_sales_order_freight[is_deleted] = False` in
  `definition/report.json` (applies to every page).
- **Drill-through** — `lineDetail/page.json` declares `pageBinding: Drillthrough` + a `Drillthrough` filter on
  `fact_sales_order_freight[shipment_number]`; right-click a Detail-page row → Drill through → Line Detail.
- **Conditional formatting** — Variance < 0 → red font, CM % → data bars on `tableDetail` and `tableOutliers`; the
  Total Variance card turns red when negative. (Hand-authored to the PBIR schema; open once in Desktop to confirm
  rendering — any rejected format object is isolated to its visual and won't affect data.)
